# Runtara Core: current and proposed tenant-scoped APIs

Proposed design, based on the current source at commit `849cf856`. No runtime changes are implemented here. This refines the [shared-tenancy transition plan](shared-tenancy-transition.md): tenant enumeration belongs to the embedding environment; scheduling, recovery, and maintenance then use the same tenant-scoped operations as other callers. There is no second, unrestricted lifecycle API.

**API convention used in these tables**

Core accepts an externally established tenant identity. It does not authenticate users, enumerate tenant assignments, check memberships, or select a tenant from configuration. A validated `TenantId` validates representation only; it is not proof that the caller is authorized. The host establishes that authority.

Keep the existing `Persistence` trait and `InstanceHandlerState`. Every tenant-specific operation receives a mandatory `tenant_id: &TenantId`: first after `&self` for persistence methods, and after `state` for handlers. In the proposed signatures below, every `tenant_id` argument has type `&TenantId`; it is never optional. Names in the second column are proposals. Arguments abbreviated as `…` remain unchanged. Persistence methods implicitly take `&self`.

The persistence implementation and connection pool can be shared across tenants. Every actual query/mutation must enforce the supplied tenant, including trait defaults, child-table joins, and nested helper calls. An ownership precheck followed by an unrestricted write is insufficient. `health_check` and capability discovery remain infrastructure operations without a tenant argument. No tenant-bound persistence wrapper is required.

```rust
// Proposed shape; not code that exists today.
// tenant_id: TenantId, supplied by the trusted host.
handle_checkpoint(&state, &tenant_id, request).await?;
persistence.get_instance(&tenant_id, &instance_id).await?;

// Environment responsibility, outside runtara-core:
for tenant in tenant_directory.assigned_tenants().await? {
    let claimed = persistence
        .claim_sleeping_instances_due(&tenant.id, limit, retry_at)
        .await?;
    environment.launch_claimed(&tenant.id, claimed).await?;
}
```

The example illustrates boundaries, not a complete scheduler: production needs bounded batches, fairness, claim validation, and execution-authority propagation. The host must not let guests choose the trusted `tenant_id` argument. Passing `&TenantId` ensures explicit context, not authorization by itself.

Retain globally unique instance IDs for this transition. Tenant scoping does not require changing primary keys to allow identical instance IDs in different tenants. Such a change would affect URLs, durable references, and artifacts and needs a separate migration.

**Common behavior and error rules**

- **Owned or missing:** a targeted lookup must not disclose another tenant's status, data, or owner. Foreign and nonexistent instance IDs have the same public missing result. Do not expose a resource-based `TenantMismatch` response.
- **Optional instance lookup:** retain `Ok(None)` for both nonexistent and foreign instances. Handlers decide how to render it using their existing contract.
- **Child lookup:** resolve the tenant-owned parent first, within the scoped operation. A missing/foreign parent is `InstanceNotFound`; an owned parent with no checkpoint or signal can still return `Ok(None)`.
- **Guarded outcomes:** preserve documented `false`, rejected decisions, and empty batches for ordinary state races or no eligible work. Never convert a storage failure into those outcomes. Where an API intentionally treats missing targets as a no-op, foreign targets must behave identically and cannot be modified.
- **Mutation scope:** constrain both the ownership check and mutation. Preserve atomicity of claims, acknowledgments, and fenced writes. Ownership is immutable; compound operations still need appropriate transaction/lifecycle guards against deletion, cancellation, and stale execution.
- **Retries:** nonexistence, invalid scope, and stale authority are not transient database failures. Storage failure does not authorize proceeding. Retry only under each operation's existing idempotency guarantees; appending an event is not automatically safe to retry after an uncertain commit.

**Persistence: instance identity, lifecycle, and input**

The following methods are defined by core's [Persistence trait](../../crates/runtara-core/src/persistence/mod.rs), even though the production SQL implementation lives in `runtara-store-postgres`.

| Current API | Proposed tenant-scoped API | Required/suggested behavior and tenancy error handling |
| --- | --- | --- |
| `register_instance(instance_id, tenant_id)` | `register_instance(tenant_id, instance_id)` | **Required:** insert with the supplied tenant. Keep global ID uniqueness. Any collision returns sanitized `InstanceAlreadyExists`; never adopt an existing foreign row or expose its owner. Creation is atomic. |
| `try_register_instance(instance_id, tenant_id, input)` | `try_register_instance(tenant_id, instance_id, input)` | **Required:** `true` = inserted; `false` = already exists in this tenant. A global ID collision outside scope is a sanitized registration conflict (`InstanceAlreadyExists`), never an idempotent same-tenant hit. Persist input atomically where this contract is relied upon. Remove the non-atomic default from production-capable implementations; no read-error fallback. |
| `get_instance(instance_id)`; `get_instance_meta(instance_id)` | `get_instance(tenant_id, instance_id)`; `get_instance_meta(tenant_id, instance_id)` | **Required:** query by tenant and instance. Foreign/missing → `Ok(None)`; storage failure → `Err`. Preserve `get_instance_meta` omission of input. The default implementation must delegate to the scoped lookup. |
| `update_instance_status(instance_id, status, started_at)` | `update_instance_status(tenant_id, instance_id, status, started_at)` | **Required:** scoped UPDATE; no row → `InstanceNotFound`. | `update_instance_checkpoint(instance_id, checkpoint_id)` | `update_instance_checkpoint(tenant_id, instance_id, checkpoint_id)` | **Required:** update only the scoped parent and ensure any referenced checkpoint is addressed within that parent. Foreign/missing parent → `InstanceNotFound`; never expose another tenant's checkpoint existence. |
| `complete_instance(CompleteInstanceParams)` | `complete_instance(tenant_id, params)` | **Required:** use the explicit `tenant_id` argument to scope the guarded mutation. Preserve `false` for a guarded no-match and `InstanceNotFound` for an unguarded missing target; foreign targets follow the same respective behavior. Output/error/stderr/run label cannot reach a foreign row. Do not turn storage errors into `false`. |
| `store_instance_input(instance_id, input)` | `store_instance_input(tenant_id, instance_id, input)` | **Required:** owned parent only; foreign/missing → `InstanceNotFound` on supporting backends. **Suggested:** declare input-storage capability explicitly instead of silently inheriting the current successful no-op. Scheduler enumerates tenants outside core rather than passing `None`. |
| `count_active_instances()` | `count_active_instances(tenant_id)` | **Required:** count running instances in this tenant only; preserve suspended exclusion. Propagate count failure. **Suggested:** use an atomic reservation/admission operation if this count is a hard limit: count-then-register cannot enforce a concurrent quota alone. Host retains global capacity admission. |
| `mark_instance_running(instance_id, started_at)` | `mark_instance_running(tenant_id, instance_id, started_at)` | **Required:** scoped read/update, preserve original start semantics. Fix the default's catch-all read fallback so storage/scope failure does not become permission to write. Missing/foreign → `InstanceNotFound`. Lifecycle/lease guards remain a separate obligation. |
| `mark_instance_started(instance_id, started_at)` | `mark_instance_started(tenant_id, instance_id, started_at)` | **Required:** scope the guarded promotion. Preserve `false` for nonmatching/missing/foreign rows; do not reveal which. Retain pre-run-state guard and timestamp behavior. Storage failure remains an error; SQL backend must apply guard and write atomically. |

**Invocation fencing: preserve and integrate existing tenant enforcement**

Sources: [InvocationFences](../../crates/runtara-core/src/persistence/invocations.rs) and [PostgreSQL implementation](../../crates/runtara-store-postgres/src/invocations.rs). `InvocationLease` already carries `tenant_id`; `AttemptFence` contains that lease. SQL locks the root using tenant and instance identity. Existing `FenceRejection::UnknownRoot` intentionally hides roots owned by other tenants.

| Current API | Proposed tenant-scoped API | Required/suggested behavior and tenancy error handling |
| --- | --- | --- |
| `Persistence::invocation_fences() -> Option<&dyn InvocationFences>` | `Persistence::invocation_fences() -> Option<&dyn InvocationFences>` — unchanged discovery | **Required:** capability discovery returns no tenant data. Every tenant operation on the returned capability requires an explicit `&TenantId`. Preserve capability optionality; when a workload requires fencing, missing capability must reject admission, never fall back to unchecked writes. |
| `get_invocation_lease(tenant, instance)` | `get_invocation_lease(tenant_id, instance)` | **Mostly already correct:** replace the existing tenant string argument with `&TenantId` and retain it explicitly. Preserve `UnknownRoot` for nonexistent/foreign root, and `Ok(None)` only for an owned root without a lease. Do not confuse lease absence with root absence. |
| `claim_invocation_lease(tenant, instance, owner, expected_epoch)` | `claim_invocation_lease(tenant_id, instance, owner, expected_epoch)` | **Required:** preserve tenant ownership and atomic epoch/CAS checks. `UnknownRoot` hides foreign roots; inactive root and lease conflict retain their existing rejection semantics. A different tenant can never claim the same root. |
| `revoke_invocation_lease(lease)`; `begin_invocation_attempt(lease, path, start_id)` | `revoke_invocation_lease(tenant_id, lease)`; `begin_invocation_attempt(tenant_id, lease, path, start_id)` | **Required:** compare the lease tenant with the explicit `&TenantId` before storage access. A mismatched token returns non-disclosing `UnknownRoot` without touching another tenant. Preserve revocation idempotency and attempt/start identity semantics. |
| `cancel_invocation_attempt(fence)`; `settle_invocation_attempt(fence, checkpoint)` | `cancel_invocation_attempt(tenant_id, fence)`; `settle_invocation_attempt(tenant_id, fence, checkpoint)` | **Required:** fence tenant must match the explicit `&TenantId`, then existing root/lease/attempt checks apply atomically. Preserve cancel-vs-settle arbitration and tombstones. Rejected fence never causes an unfenced retry. |
| `invocation_checkpoint(fence, checkpoint)`; `invocation_sleep_checkpoint(fence, checkpoint)` | `invocation_checkpoint(tenant_id, fence, checkpoint)`; `invocation_sleep_checkpoint(tenant_id, fence, checkpoint)` | **Required:** scope plus fence enforced in the same transaction. Preserve the distinction: ordinary fenced checkpoint is first-write-wins with empty-state probe; sleep checkpoint is an upsert including empty bytes. No state changes after `UnknownRoot`/lease rejection. |
| `invocation_retry(fence, retry)`; `invocation_event(fence, event)` | `invocation_retry(tenant_id, fence, retry)`; `invocation_event(tenant_id, fence, event)` | **Required:** preserve tenant-bound audit/event writes and existing identity bounds. Keep `Rejected(...)` distinct from `Storage(...)`. Observer notification follows successful commit only. Event append remains non-idempotent. |

Invocation-fence methods receive the same mandatory `tenant_id: &TenantId` argument as other tenant operations. Existing lease/fence tenant fields remain durable authority and must match that argument before any lookup or mutation. Do not derive a missing argument from a guest-supplied lease, and do not discard the lease's tenant field or change its stored representation as part of this API migration.

**Types, pure policy, and error propagation**

| Current API/contract | Proposed version | Required/suggested behavior and tenancy error handling |
| --- | --- | --- |
| `InstanceRecord { tenant_id, … }`; child records carry `instance_id` | Keep stored tenant identity; optionally use validated identity types at Rust boundaries | **Required:** backend results cannot contain another tenant's record. Child records need not gain a tenant field merely to support scoped access; SQL must join/check the owning instance. Tenant ownership is immutable through ordinary operations. |
| `CompleteInstanceParams` and instance request DTOs | Keep instance targets; pass `tenant_id: &TenantId` as a separate method argument | **Required:** never trust a payload tenant as independent authority. | `InstanceMetricsSink::on_terminal(&InstanceCompletionMetrics)` | Same signature | **Already tenant-aware:** completion metrics contain `tenant_id`. Populate it from the owned record/scoped operation. Emit metrics only for the committed outcome, not foreign or rejected mutations. |

| `CoreError::{InstanceNotFound, CheckpointNotFound, InstanceAlreadyExists, InvalidInstanceState, ValidationError}` | Reuse existing variants where they express the result | Ownership filtering happens before state-specific errors. | Registration `success: false` plus drain/cap error sentinels | Preserve legacy response adapter; typed refusals can be introduced internally | **Required:** keep existing drain/cap wire behavior during migration. Enforced tenant admission must not fail open when counting fails. Missing externally authenticated identity is rejected by the host before core; do not add JWT-style 401 errors to core. |
| `InvocationFenceError::{Rejected(FenceRejection), Storage(String)}` | Preserve existing distinction; optionally make storage failures more structured | `UnknownRoot`/`InvalidIdentity` → reject operation, no broadening/retry as another tenant. `LeaseMismatch`/`AttemptMismatch` → stop stale work and let host reconcile authority. `Busy` may be retried by scheduling policy; `Cancelled`/`Settled` preserve arbitration semantics. Storage failure never grants permission to continue. |

Transport rendering must preserve the existing operation-specific contract: for example, a status handler's intentional `StatusUnknown` response is not automatically changed to HTTP 404 merely because lookup returned `None`. Do not disclose raw database messages or foreign IDs from integrity errors. A claimed backend invariant violation should alert operators and stop the affected operation, not cause an unrestricted retry.

**Backward-compatible implementation sequence**

1. Introduce the validated `TenantId` type and new tenant-parameter entry points alongside existing contracts. Transitional method/trait names can differ until the source migration is complete. Add conformance tests before switching callers. SQL must enforce the explicit argument, not merely precheck ownership and issue an unscoped write.
2. Add handler entry points taking `(state, tenant_id: &TenantId, request)`, preserving existing request/response bodies through transport adapters. A legacy registration tenant must match the explicit trusted argument. Keep `InstanceHandlerState` as shared dependencies/settings, not an implicit source of identity.
3. Migrate requests, host imports, registration, environment lifecycle, schedulers, and cleanup to pass `&TenantId` through every call, including trait default implementations and invocation fences. Environment enumerates assigned tenants externally; one configured tenant is the first directory implementation.
4. Keep legacy Rust APIs only behind a dedicated, explicitly single-tenant adapter during migration. No fallback may infer authority by looking up an arbitrary requested instance ID. Typed trait changes need staged source migration; unchanged wire contracts do not imply Rust source compatibility.
5. Make strict/shared construction require explicit tenant parameters end to end; legacy adapters cannot be enabled for shared storage. Remove old unrestricted entry points after their compatibility window and only after all callers/backends are migrated. Do not introduce `Option<&TenantId>` or a default tenant inside core to ease the transition.

Minimum conformance additions: same-tenant success; known foreign and missing targets; registration collisions; mixed-ID deletion batches; optional child absence; failed backend reads; atomic concurrent wake claims; lifecycle/ack races; wrong-tenant/stale invocation leases; scoped pagination/counts/retention; and pool reuse between tenants. Run these against the in-memory reference backend and PostgreSQL implementation, plus protocol adapters that preserve error identity.

This document inventories production-facing handlers, the complete `Persistence` and `InvocationFences` operation families, and relevant state/error contracts. Test constructors, serialization conversions, and data-only helper methods are not separate tenancy operations. It does not invent a core `cancel_instance` or tenant-directory API: cancellation today is expressed through persistence signals/lifecycle operations, and orchestration resides outside core.
