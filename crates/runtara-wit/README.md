# runtara-wit

Canonical WIT contracts of every runtara component, in one place.

Components reach the platform through `runtara:api` (`wit-p3/api`), the
workflow API as a component interface, served by the `runtara:api` component
the compiler composes into every artifact. The other packages:

| Package | Imported / exported by |
|---|---|
| `runtara:agent` | every component (`types`); the agent export shape |
| `runtara:workflow` | compiled workflow logic: host-served `tasks`, and lowering vocabulary (`runtime`) |
| `runtara:workflow-stdlib` | the compiler-private JSON stdlib component |
| `runtara:trusted` | approved trusted agents (`execution`, called by the host executor) |

Lowering vocabulary is what workflow logic is emitted against before the
compiler serves it inside the artifact from `runtara:api`; no host links it.
Each agent also exports its own `runtara:agent-<id>` package, generated by
`agent_package`, so composition can tell agents apart.

## Using it

- **Names:** use the constants (`runtara_wit::api::RUN`,
  `runtara_wit::workflow::TASKS`, …) instead of string literals.
- **Guest bindings:** point `wit_bindgen::generate!` at `wit/<package>` or
  `wit-p3` directories; proc macros use `runtara_wit::WIT_DIR` for absolute
  paths.
- **Compiler and tests:** `resolve()` (feature `resolve`) returns one
  `wit_parser::Resolve` holding every package, in dependency order.

## Versioning

Released WIT is never edited, only versioned. The one exception was the move
to the workflow API, which retired the host ABI (`runtara:control`, `runtara:host`,
`trusted/executor`, `agent/continuation`) and requires every
workflow to be recompiled. An additive change (a new
function or interface) bumps the package minor version, and the host links only
the newest minor. Any change to an existing function or type bumps the major
version, and the host keeps linking the old major until no parked run needs it.

## Tests

```bash
cargo test -p runtara-wit --features resolve
```
