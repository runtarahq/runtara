# runtara-agent-macro

[![Crates.io](https://img.shields.io/crates/v/runtara-agent-macro.svg)](https://crates.io/crates/runtara-agent-macro)
[![Documentation](https://docs.rs/runtara-agent-macro/badge.svg)](https://docs.rs/runtara-agent-macro)
[![License](https://img.shields.io/crates/l/runtara-agent-macro.svg)](LICENSE)

Procedural macros for declaring runtara agent capabilities, input/output schemas, connection types, and step metadata.

## What it is

A `proc-macro` crate providing `#[capability]`, `agent_component!`, and four
metadata derives. `#[capability]` generates metadata, input coercion, error
normalization, and execution adapters. `agent_component!` generates the built-in
Agent's standard Component Model callback bindings, async export, dispatcher,
and typed error conversion. The metadata types live in `runtara-dsl::agent_meta`.

All 27 standalone agents under `crates/agents` use the same component plumbing:

```rust,ignore
runtara_agent_macro::agent_component!(
    agent = "http",
    capabilities = [http_request],
);
```

The list contains functions already annotated with `#[capability]`; wire IDs
come from those annotations, including explicit IDs that differ from function
names. Bindings are generated by `wit-bindgen` during the normal Cargo build.
No generated `bindings.rs`, task registry, boxed dispatcher, or feature selector
is introduced. The macro targets the built-in `runtara:agent-*/agent` worlds and
existing WIT paths under the agent crates.

Both sync and async capability functions have a uniform, directly awaited
component adapter. Native executor descriptors keep their existing types.
An async capability owns its awaited helper/I/O futures, so standard cancellation
can drop that entire chain. Wrapping a sync function does **not** introduce
cooperation points inside a CPU loop or blocking library call. Those operations
still require bounded yields or emergency whole-workflow abort.

The optional `decode_input = function_name` hook preserves input conventions,
such as datetime's empty/whitespace-to-null normalization (typed validation still
rejects null where a struct is required). It returns
`Result<serde_json::Value, serde_json::Error>` and does not customize cancellation.
Error conversion preserves explicit `retryable`; otherwise transient errors are
retryable and permanent errors are not. Input and unknown-capability errors
retain their existing codes.

## Using it standalone

The macros generate paths like `runtara_dsl::agent_meta::CapabilityMeta`, so any direct consumer must also depend on `runtara-dsl`:

```toml
[dependencies]
runtara-agent-macro = "4.0"
runtara-dsl         = "4.0"
serde               = { version = "1", features = ["derive"] }
serde_json          = "1"
```

```rust
use runtara_agent_macro::{capability, CapabilityInput};

#[derive(CapabilityInput, serde::Deserialize)]
pub struct AddInput { pub a: i64, pub b: i64 }

#[capability(module = "math", id = "add", description = "Sum two ints")]
pub fn add(i: AddInput) -> Result<i64, String> { Ok(i.a + i.b) }
```

Standalone WASM agents depend on this macro crate directly; `runtara-agents` is host-only support.

## Inside Runtara

- Primary consumers: standalone component crates under `crates/agents/runtara-agent-*`.
- `runtara-agents/src/agents/extractors/*` uses `#[derive(ConnectionParams)]` for the built-in connection types (`http_bearer`, `http_api_key`, `sftp`).
- Generated metadata targets types in `runtara-dsl::agent_meta` and is indexed by each component's `agent_info()` registry.
- Deps: `syn` 2 (full/parsing/extra-traits), `quote`, `proc-macro2`, `darling` 0.20.
- The `#[capability]` executor wrapper normalizes errors into JSON envelopes (`code` / `message` / `category` / `severity`) so the `#[resilient]` layer can make retry decisions.
- Runs in: proc-macro at compile time.
